### 1.0 Microsoft Planetary Computer（**免注册，推荐**）

```bash
# 1) 检索
curl -X POST "https://planetarycomputer.microsoft.com/api/stac/v1/search" \
  -H "Content-Type: application/json" \
  -d '{"collections":["sentinel-2-l2a"],"bbox":[114.2,30.35,114.45,30.55],
       "datetime":"2025-08-16T00:00:00Z/2025-08-16T23:59:59Z",
       "query":{"eo:cloud_cover":{"lt":10}},"limit":5}'

# 2) 读像素前必须换签名 URL（否则 HTTP 409）
curl "https://planetarycomputer.microsoft.com/api/sas/v1/sign?href=<asset.href>"
```

**踩坑记录（3 个，务必按此处理）**：

1. **409** —— COG 在 Azure Blob 上，直连报 409，必须先经 signing 接口换带 SAS 的 URL。
2. **504/503** —— signing 接口偶发抖动，需重试（脚本已内置 5 次退避重试）。
3. **窗口算成0x0、读到全 0** —— 影像 CRS 是 **UTM（如 EPSG:32650）**，
   而 bbox 是**经纬度**；`from_bounds()` 要求两者同 CRS，
   必须先用 `rasterio.warp.transform("EPSG:4326", ds.crs, ...)` 转换。

> ⚠️ 另有一个**极隐蔽**的坑：单波段用 `boundless=True` 读取时，
> rasterio 可能直接返回**二维** `(H,W)` 而非三维 `(1,H,W)`。
> 此时 `arr[0]` 取到的是**第一行**而非首个波段 → 后续运算退化成一维，
> **统计值照样算得出来、只有形状不对**，极难察觉。
> 必须用 `while a.ndim > 2: a = a[0]` 稳健解包，并断言三者形状一致。

## 二、农业保险遥感解译方法

### 2.1 指数公式（Sentinel-2 波段对应）

| 指数 | 公式 | 波段 | 分辨率 | 农险用途 |
|---|---|---|---|---|
| **NDVI** | (B08−B04)/(B08+B04) | 近红外/红 | 10m | 植被长势、产量预估 |
| **NDRE** | (B8A−B05)/(B8A+B05) | 窄带红边 | 20m | 作物 chlorophyll 胁迫（比 NDVI 更早发现) |
| **NDWI** | (B03−B08)/(B03+B08) | 绿/近红外 | 10m | 水体/洪涝淹没识别 |
| **NDMI** | (B08−B11)/(B08+B11) | 近红外/短波红外 | 20m | 冠层含水量、干旱胁迫 |
| LST | — | — | — | S2 无热红外，需另接 MODIS LST |

### 2.2 长势分级（农险口径）

| NDVI | 等级 |
|---|---|
| < 0.20 | 差 |
| 0.20 ~ 0.35 | 较差 |
| 0.35 ~ 0.50 | 中 |
| 0.50 ~ 0.65 | 良好 |
| > 0.65 | 优 |

### 2.3 灾损评估（**定损核心方法**）

```
损失率 = 1 − NDVI_灾后 / NDVI_灾前基线
```
- `NDVI_灾前基线`：同一地块、同生育期的**历史多年平均**（不是当天）
- 必须做**生育期配准**：不同生育期对灾害的响应不同，直接比差值会失真
- 行业改进做法：把 NDVI 变化量**标准化到统一尺度**后再算损失率，
  地面验证决定系数通常 0.75~0.85

**损失率→赔付档位**（行业惯例）：

| 损失率 | 等级 | 赔付比例 |
|---|---|---|
| 0 ~ 5% | 未受灾 | 0 |
| 5% ~ 30% | 轻度受灾 | 30% |
| 30% ~ 70% | 中度受灾 | 50% |
| 70% ~ 95% | 重度受灾 | 80% |
| > 95% | 绝收 | 100% |

### 2.4 涝渍判别（多指数组合）

洪涝不是单看 NDVI 下降，需组合判断：
```
NDWI > 0.10        → 疑似渍涝
NDWI > 0.35 且
NDVI 比基线低 30%+ → 确认淹没
```

### 2.5 必须做的质量控制

1. **云掩膜**：用 `SCL_20m`（场景分类）剔除
   - 3=云、2=暗影、11=雪、1=饱和
   - 保留：4=植被、5=裸土、6=水、7=人工
2. **反射率缩放**：S2 L2A 定量系数 `REF = 10000`
3. **剔除无效值**：0 与负值
4. **云量门限**：选 `eo:cloud_cover < 20%` 的景
5. **多源交叉**：光学的云遮挡需用 Sentinel-1 SAR 补

### 2.6 空天地一体化（行业标准流程）

```
卫星（宏观普查，锁定受灾边界）
  ↓ 发现异常
无人机（县域巡检，高分辨率复核）
  ↓
地面查勘（最终定损依据）
```
