# 阳光3S遥感平台（测试版）

省 → 市 → 县 → 乡 → 村 五级下钻 + 真实卫星影像 + 遥感专题反演。

## 功能
- **全国遥感地图**：34 个省级行政区及九段线，五级逐级下钻
- **资质资格地图**：1422 条经营资质、271 条政策性农险资格上图
- **承保信息上传**：上传本司承保台账，按县/乡镇空间化上图
- **8 类遥感专题**：NDVI / 地上生物量 / 干旱指数 / 土壤墒情 / 有效积温 GDD /
  地表温度 LST / 洪涝淹没 / 冰雹大风
- **真实卫星底图**：Esri World Imagery（免 KEY 亚米级）
- **真实 Sentinel-2 反演**：NDVI / NDRE / NDWI / NDMI（免注册数据源）

## 承保信息上传

支持 `.xlsx` / `.csv` / `.txt`。字段按别名自动识别（保单号、被保险人、作物、
承保面积、保额、保费、乡镇、行政村、县、经纬度、起保日期等 13 类），
识别不准可手动改。表头前的「XX分公司承保明细」这类说明行会自动跳过。

县名按全国 1733 个县级行政区匹配 adcode，含撤县设市等历史名称
（如「监利县」自动匹配现名「监利市」）。重名县（通州区/新城区/铁西区等）
须在表中带省份才能判定，否则不会猜测，会列入「未匹配」清单。

> **数据安全**：承保明细含被保险人身份与保单信息，属敏感数据。
> 本平台为纯静态站点，文件**全程只在浏览器内存中解析，不上传任何服务器**，
> 关闭页面数据即消失。点「留存到本机」仅写入本机浏览器 localStorage，
> 可随时「清除本机数据」。**请勿把含农户信息的台账放在共享机器上留存。**

在监灾点影响分析按**省级**粒度求交（平台在监灾点数据只到省），
不输出县级受灾保单数——那属于编造数据。

### 相关构建脚本
```bash
python3 tools/build_county_ref.py        # 由县界数据生成县级参照索引
python3 tools/patch_direct_counties.py   # 补齐省直辖县级行政区 + 历史名称别名
python3 tools/verify_county_ref.py 40    # 对权威源逐县核验落点精度
python3 tools/make_test_uw_xlsx.py out.xlsx   # 生成测试台账
```

## 快速开始
纯静态站点，无需构建。任选其一：
```bash
# 本地预览
python3 -m http.server 8080
# 浏览器打开 http://127.0.0.1:8080/index.html
```

## 数据口径
- 行政边界：阿里云 DataV.GeoAtlas 公开边界服务
- 资质资格：专家包 08 库《阳光农险资质与政策性农险资格地区台账》，基准 2026-08-14，内部脱敏
- 影像底图：Esri World Imagery

> **⚠️ 合规提示**：影像底图默认接入的 Esri World Imagery 服务节点位于境外，
> **仅限内部演示与方案验证，不得用于出单、定损、定价等对外业务出图**。
> 境内业务出图须改用天地图／腾讯位置服务／高德等具备测绘资质的境内服务商。
> 详见 README 正文「数据与合规声明」章节。

本平台为**演示版本**。全部承保、赔付、保费、精度指标均为模拟测算或行业公开口径引用，
不代表阳光财产保险股份有限公司真实经营数据，不构成任何业务承诺。
